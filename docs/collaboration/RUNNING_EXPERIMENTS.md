# Running experiments

## Which files are authoritative
Config under `configs/` (identified by config hash) + the planning documents
(parent folder). See `docs/decisions/AUTHORITY_AND_PROJECT_FILES.md`.

## Pinned models and datasets
Model and dataset revisions are pinned in code, not left on a moving branch:
- Model: `configs/p0/p0_1p5b.yaml` (`scientific.model.revision`) and
  `scripts/pin_model_revision.py`.
- Datasets: `heirloom/data/sources.py` (registry) — `acquire()` refuses an
  unpinned `main`. Resolve a commit with `sources.resolve_revision(...)`.

## What is downloaded separately
Nothing dataset/model-sized is in git. On first use the pinned model and
datasets download into `$HEIRLOOM_DATA_ROOT/hf_cache`. See `data/README.md`.

## Launching from config (data build; P0 example)
The P0 data freeze (no training) is driven by `configs/p0/*.yaml`:
```bash
~/.venvs/heirloom-ml/bin/python scripts/p0_freeze.py            # full corpora
```
It runs the trigger absence scan, builds the four branches for both seeds, and
verifies correspondence/rate/clean-control. It launches NO training.

## Where outputs land
- Raw run outputs: `runs/<EXP_ID>/<run_id>/` (git-ignored) with
  `provenance.json`, `config_snapshot.yaml`, and a summary file.
- Processed results: `results/<EXP_ID>/{manifests,per_seed,aggregate,diagnostics}/`.
- Run index: `runs/registry.jsonl`; experiment registry:
  `results/experiment_registry.csv`.

## Regenerating tables/figures
Tables and figures are generated by `heirloom/analysis/` from files under
`results/` into `tables/{supervisor,paper}/` and `figures/{supervisor,paper}/`.
Never hand-copy a number into a table or the paper.

## Before committing
Run `pytest -q`. Do not commit weights, checkpoints, datasets, caches, or raw
run outputs (`.gitignore` blocks these).
